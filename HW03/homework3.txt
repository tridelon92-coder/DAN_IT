1. Етапи завантаження системи Linux?
Linux не запускається одразу. Система проходить кілька етапів:

BIOS / UEFI → 2. Bootloader → 3. Kernel → 4. systemd → 5. Система готова

① BIOS / UEFI
Це перше, що запускається після увімкнення комп'ютера.
BIOS/UEFI перевіряє основне обладнання:
- процесор;
- RAM;
- диски;
- клавіатуру;
- інші пристрої.
Потім шукає диск, з якого потрібно завантажити систему.

② Bootloader — завантажувач
У Linux часто використовується GRUB.
GRUB знаходить Linux і запускає його ядро.
Якщо встановлено декілька операційних систем, GRUB також може показати меню з наявними системами для завантаження.

③ Kernel — ядро
Далі завантажується Kernel.
Він починає працювати з:
CPU → RAM → дисками → драйверами → пристроями → процесами

④ systemd
Після запуску Kernel потрібно запустити решту системи.
У сучасній Ubuntu цим переважно займається systemd.
Він запускає різні служби, наприклад:
- мережу;
- SSH;
- Bluetooth;
- графічний інтерфейс;
- інші системні сервіси.

⑤ Система готова
Після цього з'являється екран входу або Terminal.

2. Як переглянути системні журнали?
Системні журнали (logs) — це записи про те, що відбувається в Linux.

У системах із systemd одна з головних команд:
journalctl - Вона показує системний журнал.
Для перегляду журналу поточного завантаження:
journalctl -b

Для перегляду останніх записів:
journalctl -e

А для конкретної служби, наприклад SSH:
journalctl -u ssh

Ще одна корисна команда:
dmesg
Вона показує повідомлення Kernel, особливо пов'язані з обладнанням і драйверами.

Також традиційні журнали можна знайти в:
/var/log/ - каталог із файлами журналів, подивитися їх можна за допомогою команди ls

3. Що означає -rw-------?
Це права доступу до файлу.
Розділимо:
- | rw- | --- | ---
|    │     │     │
|    │     │     └── права для інших користувачів
|    │     └──────── права для групи
|    └────────────── права для власника
|_____ тип файлу

Типи файлу:
- - звичайний файл
d - директорія
l - символічне посилання або посилання на файл(щось схоже на ярлик у Windows)
c - це пристрої, які працюють із даними посимвольно або як потік байтів.
b - це пристрої зберігання даних, наприклад диски.
p - Pipe — спеціальний файл для передачі інформації між процесами.
s - Socket використовується для зв'язку між програмами/процесами.

Файл може містити такі права:
r = read    → читання
w = write   → змінювання
x = execute → виконання

Щоб зробити файл виконуваним:
Використовуємо команду:
chmod +x filename
       |
       |_________це добавить значення на виконання для всіх категорій(Власник, Група, Інші Користувачі)

Також можна добавити, кому саме дати відповідні права:
Наприклад:
u+x - Це добавить право на виконання лише власнику
g+x - Це добавить право на виконання лише групі
o+x - Це добавить право на виконання лише іншим користувачам

Всі значення:
u - Власник
g - Група
o - Інші користувачі

Також ці команди можна комбінувати або використовувати для нам потрібних категорій: 
u+rwx , g+wr, o+r або можемо забирати права якщо замінемо + на -

Також можна використовувати числове кодування:
Наприклад:
rwx = 4 + 2 + 1 = 7
rw- = 4 + 2     = 6
r-x = 4 + 1     = 5
r-- = 4         = 4
--- = 0
Це числове значення для окремого права:
r = 4
w = 2
x = 1

Щоб отримати такі права (-rwxr-xr-x)

Використовуємо chmod 755 filename

Бо:
Власник: rwx = 7
Група:    r-x = 5
Інші:     r-x = 5

4. Різниця між apt і dpkg
Обидва використовуються для встановлення програм у Debian/Ubuntu, але працюють на різних рівнях.

dpkg — це більш низькорівневий інструмент для роботи безпосередньо з пакетами .deb.
Наприклад, якщо є файл для встановлення:
program.deb

Його можна встановити:
sudo dpkg -i program.deb
Але є проблема.
Якщо програмі потрібні додаткові пакети,то dpkg не так зручно вирішує питання залежностей.

apt — зручніший менеджер пакетів.
Наприклад:
sudo apt install git

знайде Git → визначить залежності → завантажить потрібні пакети → встановить їх
Саме apt автоматично знаходить і встановлює все необхідне.

Головна різниця
		                між 			apt		        і 	         dpkg
Встановлює пакети:			            ✅				            ✅
Завантажує з репозиторію:		        ✅				            ❌
Автоматично працює із залежностями:	    ✅				            Обмежено
Працює безпосередньо з .deb:		    Через інші механізми		 ✅
Зручний для звичайного використання:	✅				            Менш зручний


Тому відповідь така:
apt — менеджер, він знаходить, завантажує та встановлює пакети разом із залежностями. А dpkg — інструмент нижчого рівня, який безпосередньо працює з уже наявними .deb пакетами.
